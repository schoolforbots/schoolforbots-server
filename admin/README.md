# 运营后台的页面

## 本地开发

不连服务器，只看页面、改样子：`npm run admin:mock`，在 http://localhost:5173/ 打开。`/api/...` 由 `mock/school.ts` 里的模拟学校回答：不用数据库，不用报名服务，也不用验证器，打开就是登录状态；退出以后，密码随便填，验证码填任意 6 位数字。

模拟学校照真实日历给出这几天的课（有通过的、红笔标过的、待审的、生成失败的、还没生成的）、最近 90 天的曲线、四周的复盘、40 个学生（7 号在停课、13 号被开除、21 号已退学、37 号以后还没分班）、开关和两条公告。改动只存在内存里，重启就回到开头。它照 `src/api.ts` 的格式和服务器的错误码、错误说明回答，每次回答前停一两百毫秒，加载中的样子看得到。数字和课文都是编的，和真的学校无关；和服务器对不上的地方，以服务器为准。测试用的假数据在 `src/fixtures.ts`，测试和模拟学校共用。

连本机的报名服务：`npm run admin:dev` 在 http://localhost:5173/ 打开页面，把 `/api/...` 转给本机的报名服务。用到的环境变量从仓库根目录的 `.env` 或命令行读：

- `ADMIN_PATH`：和报名服务用的是同一个变量。不设就不转发。
- `ADMIN_DEV_SERVER`：报名服务的地址，不设就是 `http://localhost:{REGISTRATION_PORT}`（默认 8080）。

报名服务给的登录 Cookie 带 Secure，本地开发用 Chrome 或 Firefox（它们把 localhost 当成安全来源）。

打包后的页面里所有地址都是相对的（`base: './'`，请求写成 `api/...`），后台路径只在服务器的环境变量里，不进仓库、不进打包结果。
