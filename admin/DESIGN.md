# 后台页面的设计方向

改后台页面之前先读这一页。新页面照这里做，要偏离就先改这一页，写清楚为什么。

## 读法

学校的后台给运营学校的人（运营者）用，只有一个账号。页面信息密、安静。

样子照 [HyperUI](https://hyperui.dev/) 的应用组件（application components）和它的分析看板模板（analytics dashboard，五页：Overview、Customers、Orders、Billing、Settings）。不是只借它的框架：卡片、标题、按钮、标签、表格、表单、开关、对话框都用模板里的那套 Tailwind 类名来写。新加的东西先在 HyperUI 里找对应的组件，照它的类名写，找不到再自己配，配的时候用同一套灰色、圆角和字号。

用 Tailwind CSS（v4，`@tailwindcss/vite`）写在组件里，不用组件库。公用的部件在 `src/ui.tsx`：按钮（`primary` 近黑、`default` 白底灰边、`danger` 白底红边红字）、输入框、单选、开关样式的按钮、对话框、卡片 `Card`、标签 `Badge`、表格的类名 `TABLE`/`TH`/`TBODY`/`TD`、详情列表 `Detail`、迷你折线 `Sparkline`、放到页头的 `PageActions`。审课页几处共用的类名在 `src/components/lesson/look.ts`。`src/styles.css` 只留主题、基础规则，以及工具类够不着的几样：图表的 SVG 和读数框、红笔、公告正文（照网站的样子）。都是原生的 HTML 元素，键盘、读屏和测试看到的就是按钮、输入框、单选和对话框。

2026-11 以前用 Ant Design 打底。换掉的原因：样子和 HyperUI 的看板对不上，每个颜色、边框、焦点框都要在主题里一项项改回来（对比度不够）；包也大（约 300 kB gzip，换掉以后整个页面约 100 kB）。

调子：ENERGY 1 / RHYTHM 1 / MOTION 1。

- ENERGY 1：页面不招呼人，打开就是数字和要做的事。
- RHYTHM 1：卡片一个样，统计卡四个一行，图表两列等宽，整齐是有意的：每天来看的人要一眼找到同一个位置。
- MOTION 1：没有动效，只有悬停、按下和焦点的样子（按钮、列表行的底色在悬停时换一下）。加载时不转圈，写字说明正在读什么。

## 只做电脑版

最小宽度 1200px，窄于这个宽度时页面横向滚动。后台按在电脑上使用来设计，不做手机适配。其余要求照常，见下面各节：颜色的对比度，写字（包括空、加载中、出错三种状态），键盘和焦点。

## 页面的框架（模板的 Overview 页）

- 侧栏 256px（`w-64`）宽，白底，右边一道细线，跟着窗口不动。最上面是校名（近黑底白字的“校”和“机器人网校 / 运营后台”两行），下面一页一行（`rounded-lg px-4 py-2 text-sm font-medium`）。最下面一格写“运营者”，下面是“退出登录”。
- 侧栏里的每一页是链接（`#data`、`#review`……），当前这一页 `aria-current="page"`，灰底（`bg-gray-100`）深字。“审课”旁边用红色小标签写待审几节（读不到就写“待审数没读到”）。
- 页头白底，下面一道细线：左边 `h1` 是这一页的名字（`text-lg font-semibold`），右边是这一页的主要操作，近黑的主按钮（模板的 “New report”）：更新到现在、给某一天指定题目、写新公告。页面用 `PageActions` 把按钮放过去；单独显示一页时（测试里）按钮留在页面里。整页只有这一个 `h1`；页面内容放在以它为名的 `main` 里。浏览器标签页的标题跟着换（“审课 · 机器人网校后台”）。
- 内容区 `p-6`，浅灰底。卡片：`rounded-lg border border-gray-200 bg-white p-6`，卡片标题是小字（`text-sm font-medium`），这一点和模板一样，卡片里的东西才是主角。一组卡片的上面用 `text-base font-semibold` 的标题分段（今天、昨天、最近 7 天）。
- 登录页：浅灰底中间一张卡片，上面是校名，近黑的登录按钮。

## 颜色

颜色写在 `src/styles.css` 的 `@theme` 里，`src/palette.test.tsx` 从那里读出来检查对比度。灰色和标签的几种颜色用 Tailwind 的（写成 hex，测试才算得准），只有 `gray-500` 比 Tailwind 的深一点。

| 用途 | 颜色 | 说明 |
|---|---|---|
| 主要按钮、焦点框 | `gray-900` `#111827` | 模板的近黑按钮，白字；悬停 `gray-800`。焦点框 2px，同一个颜色 |
| 当前的一页、选中的行 | `gray-100` `#f3f4f6` | 侧栏当前那一页、审课列表里选中的课位、按钮组里选中的那个 |
| 标签 | 绿 `green-100`/`green-800`，黄 `yellow-100`/`yellow-800`，红 `red-100`/`red-700`，靛蓝、蓝、灰 | 见下面“标签的颜色”。字和底都过 4.5:1 |
| 红笔 `red-pen` | `#c8312b` | 审核标记的波浪线和页边批注（楷体），以及学校数据页的超预算。白底上 5.34:1 |
| 页面底色 | `gray-50` `#f9fafb` | |
| 卡片 | 白，边框 `gray-200` `#e5e7eb` | 不加阴影；图表的读数框和对话框有阴影，因为它们浮在上面 |
| 不能用的按钮上的字 `disabled` | `#4b5563` | 按钮在发送时只靠这几个字说明进度（正在登录、正在删除），所以要读得清：灰底（`gray-100`）上 7.0:1 以上。灰底和“不能点”的光标仍然说明它现在用不了 |
| 输入框的边 `edge` | `#868d97` | 白底上 3.2:1，看得出输入框在哪（模板的 `gray-200` 只有 1.2:1，这是唯一比模板深的地方）。按钮的边用 `gray-300`，按钮上有字，不靠边认 |
| 正文 | `gray-900` | |
| 次要文字 | `gray-600` `#4b5563`、`gray-500` `#636a75` | `gray-500` 在灰底（`gray-100`）上也有 4.5:1 |
| 输入框提示文字 `placeholder` | `#6b7280` | 白底上 4.83:1 |
| 黑板绿 `brand` | `#2f5d50` | 只剩公告预览里的链接，照网站的样子 |

标签的颜色（`Badge`），字写清状态，颜色只是帮着看：

- 绿：好的、做完的。已通过、在读、已发布、送达、开关现在开着，以及“比上周多/少”里的好消息（来上课的学生、聊天消息、新报名变多；拦下、违规、停课、开除、花费变少）。
- 黄：要人去做、在等的。待审、停课中、已撤下、维护中。
- 红：出了问题的。红笔 N 处、生成失败、开除、拦下的消息、有效的违纪记录、超预算，以及“比上周多/少”里的坏消息。危险操作的按钮（删掉、退学、手动停课）也是红字。
- 灰：没有好坏的。没变、待生成、已开课、草稿、退学、等分班、现在关着。
- 靛蓝、蓝：只做分类（第几版、词和话术规则），不表示好坏。

表单没填的地方用红字说哪里没填，和模板的表单一样。红笔仍然只在审课页的课文和页边出现，样子（楷体、波浪线）别处不用。

图表的线按这个顺序取色（Tailwind 的 indigo-600、amber-500、emerald-500、sky-500、pink-500、violet-500、orange-600）：

`#4f46e5`、`#f59e0b`、`#10b981`、`#0ea5e9`、`#ec4899`、`#8b5cf6`、`#ea580c`

只有一条线的图在线下面铺一层同色的渐变（模板的 Revenue trend）。三条线的图取前三个，花费按七种用途取前七个。其中几种浅色在白底上不到 3:1，所以多条线的图都有图例、线尾标名字，还能切换成表格看。

只做浅色。红笔批改的样子是白纸上的红字，深色底会把这个意思弄丢；以后要加深色，两套都得能用。

## 字体

系统自带的中文字体：`"PingFang SC","Microsoft YaHei","Noto Sans CJK SC",system-ui,sans-serif`。不加载网络字体。正文 14px；统计卡上的数字 24px（`text-2xl font-medium`），是每一屏最醒目的东西。

唯一的例外是红笔批注：用系统自带的楷体（`"Kaiti SC",STKaiti,KaiTi,"AR PL UKai CN"`，没有就退回上面那组），像老师在页边手写的字，和印出来的课文分得开。审课页的课文 15px，行距 1.9，读长段落不累。

## 学校自己的特色：红笔批改

审课页上，有问题的字句下面画红色波浪线，页边写红字批注，像老师改作业。

审课页的样子（`src/pages/Review.tsx`）：

- 左边一张卡片“这几天的课”，跟着窗口不动。每天一个灰色小标题，下面每个学部一行，像侧栏的链接：状态是右边的标签（已通过、红笔 N 处、待审、待生成、生成失败、已开课、当天已定）。选中的课位灰底，左边一道深色的边，不只靠颜色区分。
- 右边一节课是一张卡片：上面一行日期和标签（学部、科目、第几版、状态），下面标题和各段用细线隔开。每一处（标题、每段正文和要点、两道点名题）右边都有自己的页边；没有标记的写灰字“没有批注”，不留空白。
- 被拒绝的改动，原因写在动手的地方，用细框框起来。
- “通过，审下一节”在卡片底部一条灰底的栏里，贴在窗口底部，读到哪里都点得到。

## 学校数据页（模板的 Overview 页）

最上面是今天，下面是昨天，再下面是“要处理的事”和曲线。今天和昨天各八张统计卡（模板的 stat card），四张一行：左上是在数什么，右上是和上周同一天比的标签（带上下箭头，写“比上周三多 4”），中间是数字，旁边小字写上周同一天的数（“上周三 120”）。今天的四张（来上课的学生、聊天消息、拦下的消息、大模型花费）下面还有最近几天的迷你折线，画的是下面曲线的同一组数，只是装饰，读屏不读。

- 今天的标题写“今天（截至 16:00）”：数字从学校时区的零点算到读取的那一刻，一节课下了课，它的数据就都在里面。比较也只截到同一时刻，不拿半天和一整天比。标题旁边写一次“和上周三零点到 16:00 的数字比。”。
- 今天的数字一直在涨，页头的“更新到现在”重新读一遍。读的时候按钮写“正在更新”，不变成不能点（那样焦点会丢），再点一次不会多读一遍。
- 今天不上课（还没开学、放假、不上自习的周末、维护中）时，标题旁边用一句话说为什么，数字照样显示：报名和大模型花费不停。
- 本月花费和预算写在今天的花费下面，本月的数里已经有今天的。
- 昨天和上周同一天的一整天比。
- “要处理的事”是一张卡片，一件事一行，左边是标签（待审、生成失败、超预算），“去审课”在右边。
- 曲线两列，每张一张卡片；7、30、90 天是卡片组右上的按钮组（模板的 6M/12M）。曲线只画到昨天：今天还没过完，画进去会像突然跌了一截。

## 每周复盘、查学生、开关、公告

- 表格照模板：表头下一道粗线，行之间细线，数字靠右、等宽。表名写在表格上面（`caption`）。
- 每周复盘：最上面一条白色的卡片选哪一周（原生 `select`，键盘直接用），旁边标签写已复盘还是还没复盘；下面一排四张统计卡（点名回答率、收到的问题、新生、大模型花费），再下面分六块：上课、课程、老师、审核、学生、花费，最后是“已删的词和已停用的规则”，方便照着改词库文件。
- 大模型的两项（修改方向、建议停用的词）分清三种情况，各说各的话：还没复盘、这一项没生成出来（写出原因）、生成了但没有建议。整周什么都没有时，不摆六块零，直接说这一周没上课也没花钱。
- 查学生：带放大镜的学号搜索框和近黑的“查这个学号”。资料卡片最上面是 AI 名字和状态标签，下面是两列的详情列表（模板的 details list）。停课、退学、解除处罚在卡片里一块红边的“手动处理”区（模板 Settings 页的 Delete team）。消息一次读一页，往下点“再读更早的消息”；被拦下的消息那一行淡红底。
- 开关（模板的 Settings 页）：维护单独一张卡片在最上面，维护中时整张卡片变黄。三个运行时开关在一张卡片里，一行一个（模板的 Notifications），右边是开关样式的按钮，名字旁边标签写现在开着还是关着；开着和关着的效果都写出来，现在生效的那句字深，另一句灰；写最近一次切换的时间。点开关不会直接切换，先弹确认框。
- 公告（模板的 Orders 页）：一张表列出全部公告，状态是标签；写和改公告照模板 Settings 页的表单：左边一栏写这一组是什么，右边是输入框，旁边是网站上的样子的预览，按钮在卡片底部的灰条里。

改了就收不回来的操作（删词、停用规则、手动停课、退学、解除处罚、切换开关、删公告）都先弹一个确认框（`components/Confirm.tsx`，样子是 HyperUI 的 modal：白卡片，按钮在底部的灰条里）：标题问要不要做，正文一句一句写后果，按钮写清做什么（“删掉这个词”“办退学”“关掉”），另一个按钮写“先不删”“先不办”；删除、退学这类用红色的按钮。焦点先落在退一步的那个按钮上，后果是它的说明，读屏会一起读出来。服务器拒绝时，原因写在框里并拿到焦点；做完了，框关掉，结果写在动手的地方并拿到焦点。

## 时间

页面上的时间都按学校的时区显示，不按这台电脑的时钟：登录和查登录状态时，服务器把时区一起给页面（`src/zone.ts`）；学校数据页用它自己那份数据里的时区；"今天"用审课列表给的学校日期。所以在别的时区打开后台，开门时间、切换开关的那一天、能指定题目的日子都不会错。

## 写字

- 页面上的字用中文，按钮写它做的事（去审课、重新读取、用表格看），不写"确定""提交"这类空话。
- 不用破折号，不在按钮和标题上放装饰用的箭头、图标或表情符号。
- 空、加载中、出错都写清原因和下一步：
  - 空："最近 7 天还没有数据。学校开学后，第二天这里会出现第一组数字。"
  - 加载中："正在读取学校数据"
  - 出错："没能读取学校数据。连不上服务器，检查网络后再试。" 加一个"重新读取"。
- 服务器给的中文原因原样显示（409、422、503 都是这样），不另编。
- 页面上的数字都来自接口；没有数字就不显示数字。

## 键盘和焦点

每个能点的东西都能用 Tab 走到，Enter 或空格能用。焦点框是 2px 的近黑（`gray-900`）；输入框聚焦时边框也变成近黑。不要去掉焦点框。图表本身也能聚焦：左右方向键逐天看数字，Home、End 到头尾，Esc 收起。

确认框：打开时焦点在"先不……"那个按钮上，Tab 在框里转，Esc 关掉，焦点回到打开它的按钮；做完以后焦点到写结果的那一句。

审课页：课的列表在 Tab 顺序里只占一站（选中的那一课），上下键换课，Home、End 到头尾。Esc 关掉对话框，也收起改字和写理由的框，焦点回到打开它的按钮（对话框关掉也一样）。点了按钮以后按钮会暂时不能用，焦点就交给接下来出现的东西：被拒绝的原因、要确认的话、通过以后下一节课的标题、点了"这是误伤"以后下一处"这是误伤"（没有了就是"通过，审下一节"），以及改到一半这节课开课时的那句说明。

一节课同时只改一处：一个改动没回来以前（重写可能要一分钟以上），别的改动按钮和打开框的按钮都暂时不能用，等着结果的框也不会被别的框挤掉。

## 图表

图表用 `src/components/LineChart.tsx` 自己画的 SVG，没有用图表库：画在 canvas 上的键盘走不到，jsdom 里也测不了，而且包很大。这里要的样子它都要自己再配一遍：

- 标题写成图回答的问题，比如"每天有多少学生来上课？"；
- 线 2px，网格线是细的实线；
- 多条线的图有图例，线尾再标一次名字，名字挤在一起时用引线错开；
- 鼠标悬停或键盘聚焦时，显示那一天每条线的数字；
- 切换过运行时开关的日子画一条竖线，读数里写出几点切换了哪个开关；
- 每张图都能切换成表格看（最新的一天在最上面）。

切换 7、30、90 天时，旧图留着、线先变淡（字不变淡，对比度不降），上面一行字说正在读哪几天，新数据到了再换，不闪空白。

## 本地开发

不连服务器，只看页面、改样子：`npm run admin:mock`，在 http://localhost:5173/ 打开。`/api/...` 由 `mock/school.ts` 里的模拟学校回答：不用数据库，不用报名服务，也不用验证器，打开就是登录状态；退出以后，密码随便填，验证码填任意 6 位数字。

模拟学校照真实日历给出这几天的课（有通过的、红笔标过的、待审的、生成失败的、还没生成的）、最近 90 天的曲线、四周的复盘、40 个学生（7 号在停课、13 号被开除、21 号已退学、37 号以后还没分班）、开关和两条公告。改动只存在内存里，重启就回到开头。它照 `src/api.ts` 的格式和服务器的错误码、错误说明回答，每次回答前停一两百毫秒，加载中的样子看得到。数字和课文都是编的，和真的学校无关；和服务器对不上的地方，以服务器为准。测试用的假数据在 `src/fixtures.ts`，测试和模拟学校共用。

连本机的报名服务：`npm run admin:dev` 在 http://localhost:5173/ 打开页面，把 `/api/...` 转给本机的报名服务。用到的环境变量从仓库根目录的 `.env` 或命令行读：

- `ADMIN_PATH`：和报名服务用的是同一个变量。不设就不转发。
- `ADMIN_DEV_SERVER`：报名服务的地址，不设就是 `http://localhost:{REGISTRATION_PORT}`（默认 8080）。

报名服务给的登录 Cookie 带 Secure，本地开发用 Chrome 或 Firefox（它们把 localhost 当成安全来源）。

打包后的页面里所有地址都是相对的（`base: './'`，请求写成 `api/...`），后台路径只在服务器的环境变量里，不进仓库、不进打包结果。
